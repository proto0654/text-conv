# text-conv

Правка **уже выделенного** текста по хоткею в Hyprland/Wayland: ровно две
операции-переключателя — раскладка (латиница ⇄ кириллица) и регистр. Без
автопереключения и без фонового демона — только два биндинга и скрипт.

```
ghbdtn? rfr ltkf/   →  Shift+Pause  →  привет, как дела.
ПРИВЕТ мир          →  Alt+Pause    →  привет МИР
```

## Возможности

- **Операций всего две**: `layout` и `case`. Каждая — тогл: повторное нажатие
  возвращает текст символ в символ, третьих режимов и «умных» вариантов нет.
- **Смена раскладки** (`layout`): `en→ru` или `ru→en` — направление выбирается по
  преобладающим буквам, так что одна клавиша работает в обе стороны.
- **Инверсия регистра** (`case`): посимвольная, `Привет` → `пРИВЕТ`.
- Правило одно: каждый символ меняется на тот, что стоит **на этой же клавише**
  в другой раскладке. Никаких исключений по месту в слове — поэтому годятся и
  знаки: `]` ~ `ъ`, `.` ~ `ю`, `,` ~ `б`, `;` ~ `ж`, `'` ~ `э`, `/` ~ `.`,
  `?` ~ `,`, `` ` `` ~ `ё`, `"` ~ `Э`. Отсюда `j,]zdktybt` → `объявление`,
  `k.,k.` → `люблю`, `vj.` → `мою`, `vjq ,jnybr` → `мой ботник`.
- Обратная сторона того же правила: знаки тоже переезжают. `,` и `.`, набранные
  английскими клавишами, станут `б` и `ю` (`Ghbdtn, rfr ltkf?` → `Приветб как
  дела,`). В русской раскладке точка и запятая живут на клавишах `/` и `?`,
  так что `ltkf/` → `дела.`, а `Ghbdtn? Rfr ltkf/` → `Привет, Как дела.`
- Преобразование обратимо: повторный `Shift+Pause` возвращает исходный текст
  символ в символ.
- Поддержка `ё`/`Ё` и shift-символов (по позициям клавиш).
- Работает в GUI-приложениях и в терминалах (там используется `Ctrl+Shift+C/V`).
- Переключает системную раскладку на тот язык, в который сконвертирован текст:
  `en→ru` включает русскую, `ru→en` — английскую (`hyprctl switchxkblayout` по всем
  клавиатурам, у которых в `kb_layout` есть нужный язык).
- Буфер обмена восстанавливается через 1,5 с — то, что у вас было скопировано,
  не теряется.

## Требования

- Hyprland (используется `hyprctl`; на wlroots-композиторах без него не заработает).
- `python3`, `wtype`, `wl-clipboard` (`wl-copy`/`wl-paste`).
- Настроенная пара раскладок `us,ru`.

Arch/Omarchy:

```bash
sudo pacman -S --needed python wtype wl-clipboard
```

## Установка

```bash
git clone https://github.com/<you>/text-conv.git
cd text-conv
./install.sh                  # кладёт скрипт в ~/.local/bin
```

Затем добавьте биндинги в `~/.config/hypr/bindings.lua` (Omarchy/Hyprland Lua-конфиг):

```lua
o.bind("SHIFT + PAUSE", "Сменить раскладку выделенного", "/home/<you>/.local/bin/text-conv layout", { release = true })
o.bind("SHIFT + BREAK", "Сменить раскладку выделенного", "/home/<you>/.local/bin/text-conv layout", { release = true })
o.bind("ALT + PAUSE", "Инвертировать регистр выделенного", "/home/<you>/.local/bin/text-conv case", { release = true })
o.bind("ALT + BREAK", "Инвертировать регистр выделенного", "/home/<you>/.local/bin/text-conv case", { release = true })
```

Классический `hyprland.conf` (не Omarchy-обвязка, а обычный Hyprland — без Lua):

```ini
bindr = SHIFT, Pause, exec, /home/<you>/.local/bin/text-conv layout
bindr = SHIFT, Break, exec, /home/<you>/.local/bin/text-conv layout
bindr = ALT,   Pause, exec, /home/<you>/.local/bin/text-conv case
bindr = ALT,   Break, exec, /home/<you>/.local/bin/text-conv case
```

Почему дублируется `PAUSE` и `BREAK`: в XKB клавиша `<PAUS>` объявлена как
`[ Pause, Break ]` с `PC_CONTROL_LEVEL2`, то есть с зажатым Shift она отдаёт
keysym `Break`, и биндинг только на `PAUSE` не сработает.

Почему на отпускание и почему **без** `ignore_mods`:

- нажатие обрабатывается на отпускании клавиши, потому что свитчер копирует
  выделение инъекцией `Ctrl+C`, а пока Shift зажат физически, Chrome/Chromium
  получает `Ctrl+Shift+C` = «Inspect element». На отпускании модификатор уже снят;
- `ignore_mods` заставил бы Hyprland вообще не сверять модификаторы
  (`KeybindManager.cpp`: `modmask != k->modmask && !k->ignoreMods`), и тогда на
  одно нажатие проходят **оба** биндинга — раскладка и регистр затирают друг
  друга, и видно то «смену регистра вместо раскладки», то «капслок». С точными
  модификаторами на нажатие срабатывает ровно один биндинг.

После правки: `hyprctl reload && hyprctl configerrors`.

## Использование

1. Выделите текст мышью (или `Ctrl+A`, `Shift+стрелки`) — либо просто поставьте
   курсор после слова, тогда скрипт возьмёт слово слева.
2. `Shift+Pause` — сменить раскладку, `Alt+Pause` — инвертировать регистр.

## Как это работает

Скрипт без демона и без чтения клавиатуры:

1. Определяет активное окно (`hyprctl activewindow`, без `-j` — импорт `json`
   стоит 10 мс) и решает, терминал это или нет.
2. Запоминает текущий буфер и жмёт `Ctrl+C` (`Ctrl+Shift+C` в терминалах) —
   модификаторы хоткея отпускает тем же вызовом `wtype` (иначе при зажатом
   Shift это `Ctrl+Shift+C`, а в Chrome это «inspect element»).
3. Ждёт, пока буфер изменится (опрос каждые 8 мс): новое содержимое и есть
   выделение. Не изменилось — повторяет аккорд, затем читает PRIMARY-выделение
   (спасает в Electron/Chromium, где синтетический `Ctrl+C` игнорируется),
   затем пробует выделить слово слева от курсора.
4. Конвертирует (`str.translate` по таблице позиций клавиш), кладёт результат в
   буфер, посылает `Ctrl+V` / `Ctrl+Shift+V`.
5. Через 1,5 с возвращает прежний буфер — но только если в нём всё ещё наш
   результат: иначе восстановление затирало бы то, что вы скопировали сами
   (или буфер следующего, быстрого нажатия).

Хоткей отрабатывает примерно за 0,15–0,25 с (замерено на окне Chromium).
Почти всё это — запуск внешних процессов, а не конвертация (`str.translate`
считает выделение за микросекунды):

| что | сколько |
|---|---|
| старт `python3` (shebang `env -S python3 -S`, без `site`) | ~12 мс |
| `hyprctl` (активное окно, переключение раскладки) | 2 × ~7 мс |
| `wtype`: отпустить модификаторы + `Ctrl+C` | ~40 мс |
| ответ приложения на `Ctrl+C` | ~12–50 мс |
| `wl-copy` результата и ожидание владения (буфером владеет чужое окно) | ~40–90 мс |
| `wtype`: `Ctrl+V` | ~30 мс |

Отсюда и потолок: чтобы стать заметно быстрее, надо перестать запускать
`wl-copy`/`wtype`/`hyprctl` на каждое нажатие — то есть обращаться к Wayland
напрямую из одного процесса (Rust/Go с виртуальной клавиатурой и data-device).
Это уже другая программа.

## Ограничения

- **Текст страницы в браузере не редактируется** — вставка просто ничего не
  делает. Работает в полях ввода, textarea, `contenteditable`, редакторах,
  чатах и терминалах.
- В терминалах вставка терминальная: внутри `vim`/`htop` это обычный paste,
  а не замена выделения.
- Смена раскладки переключает и системную раскладку, но не «запоминает» пары
  слов вроде Punto: исправляется только выделение, автоматики нет.

## Отладка

```bash
TEXT_CONV_DEBUG=1 ~/.local/bin/text-conv layout   # подробный лог
tail -20 /tmp/text-conv.log
printf 'Ghbdtn' | ~/.local/bin/text-conv layout --stdin   # проверка конвертации без GUI
```

Каждый успешный прогон пишет в лог, откуда взялся текст и сколько занял каждый
этап — по этим числам видно, где тормозит конкретное приложение:

```
ok case: 'sdf' -> 'SDF' | 142 ms via=clip | win=7 copy=42 grab=54 sent2=93 paste=142
```

`via=clip` — текст пришёл из `Ctrl+C`, `clip2` — со второй попытки,
`primary` — из PRIMARY-выделения, `word` — выделили слово слева от курсора.

## Проверено

Omarchy (Hyprland, Wayland): Chromium (поля ввода), Electron-чаты, `foot`
(терминальная ветка), Omarchy shell. Скрипт зависит от `hyprctl` и
`wl-clipboard`, поэтому на GNOME/KDE заработает только после замены определения
активного окна.
